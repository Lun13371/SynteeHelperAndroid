## ЗАДАЧИ

### 1. Производительность

**Старт и сборка:**
- Baseline Profile module (`baseline-prof.txt` + `ProfileInstaller`), прогон через
  `macrobenchmark` — цель: холодный старт < 800мс на среднебюджетном устройстве
- R8: `isMinifyEnabled`, `isShrinkResources`, proguard-rules (kotlinx-serialization,
  Retrofit, Room — стандартные keep-правила)
- Зависимости: проверка на дубликаты (`./gradlew :app:dependencies`), R8-байпас не плодить

**Compose:**
- Стабильные модели списков (`@Immutable` для Chat/ChatMessage/MessageBubble data)
- `key()` в каждой LazyColumn, `contentType` для переиспользования
- Стриминг: НЕ перекомпозировать весь список на каждый чанк — только хвостовой
  элемент (стримящееся сообщение — отдельный item, состояние через
  `derivedStateOf`/`snapshotFlow` с throttle ~50мс на батчинг чанков)
- Markdown: полный рендер — один раз после финализации (уже в стадии 03), во время
  стрима — плоский текст; кэшировать распарсенный Markdown по messageId
- `LazyColumn` в списке чатов: без вложенных рекомпозиций — `items(chats, key)`

**Память/батарея:**
- Стриминг в фоне: если приложение свёрнуто — стрим продолжает ViewModel, но
  UI не перерисовывается (пауза эмиссии в UI при `Lifecycle.State < RESUMED`)
- OkHttp connection pool — один клиент на приложение (уже так)
- Отключать рефреш статусов моделей, когда экран не виден

### 2. Анимации и UX-полировка

- Переходы навигации: fade+slide (Navigation Compose transitions), shared-element
  для аватара/названия чата (Compose 1.7+ SharedTransitionLayout) — по возможности
- Появление сообщений: мягкий fade+slide-up (~180мс, spring)
- Стриминг-курсор: пульсирующий блок на конце текста
- Bottom sheet селектора моделей: spring-физика (как motionPresets десктопа)
- Pull-to-refresh в списке чатов (рефреш статусов моделей)
- Haptics: лёгкая вибрация на отправку/стоп/копирование кода
- Скелетоны вместо спиннеров (карточки чатов, карточки моделей)

### 3. Состояния и ошибки

Единый маппинг `AppError → UiText`:
- Нет сети → баннер «Офлайн» (ConnectivityManager callback, live) + повтор
- 429 → «Слишком много запросов, подождите N сек» (из Retry-After, если есть)
- 5xx → «Gateway лёг. Попробуйте позже» + кнопка «Повторить»
- 401 после refresh → авто-logout + тост «Сессия истекла»
- Таймаут стрима (нет чанков 60с) → отмена + «Ответ прервался» + «Повторить»

Пустые состояния: список чатов (иллюстрация), поиск без результатов, гость без
провайдеров. Все с призывом к действию.

### 4. Тесты

- **Unit** (JVM): ChatSseParser (все форматы — уже с 02), ChatRepository
  (MockWebServer: стрим, отмена, ретраи, чекпоинты), AuthInterceptor (401-флоу),
  AppearanceSettings (сериализация/миграции)
- **Turbine**: ChatViewModel (стрим-состояния, автоскролл), ModelsRepository
- **Compose UI**: логин-флоу (фейк), список чатов (создать/удалить/undo), экран
  чата (отправка с фейковым стримом), настройки (переключение темы)
- Цель: критичные пути покрыты, CI-готовность (`./gradlew test` зелёный)

### 5. Релизная сборка

- Signing: keystore (не в репо! в `local.properties`/env пути), `signingConfigs.release`
- Версионирование: `versionCode` инкремент, `versionName` semver (1.0.0 — база)
- Сборки: `assembleRelease` (APK для быстрой раздачи) + `bundleRelease` (AAB для Play)
- Проверка release-сборки: R8 не сломал serialization/SSE (прогнать чат на release!)
- `README.md`: сборка, запуск (dev URL для эмулятора/устройства), структура
